# Limitations And Threats

本页提供可以直接写进正文的局限性和威胁条目。

## 当前必须承认的限制

### 1. 当前主结论仍是单 seed 正式结果

推荐写法：

> 需要指出的是，本文当前正式主结果来自 `LongBench_3tasks canonical` 的单 seed 评测，尚未完成 `3-seed + CI` 复核。因此，本文更强调“当前已验证的正式趋势”，而不是把结论表述为完全收敛的最终定论。

### 2. `single_doc_qa` 存在明确回撤

推荐写法：

> 尽管所提协议在 `overall`、`multi_doc_qa` 和尤其 `code_qa` 上取得正向收益，但其在 `single_doc_qa` 上仍出现回撤。这说明统一的 agent 协议并未自动适配所有长文档任务，特别是在答案较短、定位更直接的单文档场景中，额外的迭代与检索可能引入不必要的干扰。

### 3. 收益伴随额外成本

推荐写法：

> 本文方法并非“免费提升”。与标准单轮 RAG 相比，`edge_agent_4b` 的 `p95 latency` 比例约为 `1.333`，并出现 `3` 次 OOM。这意味着协议收益需要与运行成本和稳定性边界一并报告。

### 4. `code_qa` 虽强，但来源仍有边界

推荐写法：

> 本文将 `code_qa` 作为标题级亮点任务，主要原因在于其样本规模充足且收益显著。然而，当前 `code_qa` 主评测仍主要来自 `lcc + repobench-p`，因此本文更谨慎地将其视为高价值亮点，而非唯一身份。

### 5. 强对照与消融仍不完整

推荐写法：

> 更强的预算匹配基线、单轮强检索基线以及更完整的消融结果能够进一步增强本文的说服力。由于当前 package 以已验证结果为前提构建，本文不把这些未完成补充实验写成既成事实。
