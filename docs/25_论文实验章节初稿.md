# 25. 论文实验章节初稿

## 1. 实验目标
本文不再以“更大模型绝对分数更高”作为主目标，而是聚焦三个更适合当前系统定位的问题：

1. 在端侧部署约束下，`Qwen3 4B` 能否通过任务路由式 agent 协议，在长文档三任务上实现平衡提升。
2. 这种提升能否在 `LongBench_3tasks canonical` 上形成唯一、稳定、可复核的正式主结论。
3. 在主配置冻结后，student 路线能否进一步补充效率收益。

## 2. 研究问题

| 编号 | 研究问题 | 对应证据 |
| --- | --- | --- |
| RQ1 | `edge_agent_4b` 是否在 canonical 上优于三类强对照 | 主结果表 |
| RQ2 | 收益是否只是额外预算或更强单轮检索带来的 | 预算匹配基线、单轮强基线 |
| RQ3 | 主方法是否具备复现性与稳定性 | `3-seed confirm`、CI、round snapshot |
| RQ4 | 质量收益来自哪些机制，代价来自哪些机制 | 分组消融 |
| RQ5 | 主配置冻结后，是否还能蒸馏出更轻的 student | student 附加实验 |

## 3. 实验对象与数据

### 3.1 模型
- 主模型：`Qwen3 4B`
- 推理后端：local real backend
- 默认策略：thinking off、fact memory on、early-stop on、budget guard on

### 3.2 数据集角色

| 数据集 | 路径 | 角色 |
| --- | --- | --- |
| canonical | `data/main_eval/longbench_3tasks_test.jsonl` | 唯一论文主结论 |
| monitor_dev_cross_source | `data/main_eval/longbench_3tasks_dev100.jsonl` | 高频调参与风险监测 |
| monitor_holdout_cross_source | `data/main_eval/longbench_3tasks_holdout100.jsonl` | 跨来源风险监测 |
| quickgate30 | `data/main_eval/longbench_3tasks_quickgate30.jsonl` | 晋级预筛 |
| code_generalization_appendix | `data/main_eval/code_generalization/code_generalization_appendix.jsonl` | `code_qa` 外部效度补充 |

### 3.3 三任务口径
- `single_doc_qa`
- `multi_doc_qa`
- `code_qa`

### 3.4 canonical 规模与定位
- canonical 总规模：`2550`
- `single_doc_qa`：`750`
- `multi_doc_qa`：`800`
- `code_qa`：`1000`

这里需要特别说明 `code_qa` 的定位。当前 `code_qa` 主评测来源为 `lcc + repobench-p`。它在样本数上并不小，但任务来源仍偏“仓库级 / 补全式代码理解”，因此本文将其定位为高价值亮点任务，而不是整篇论文的唯一身份。整篇论文的主结论仍以三任务 canonical 平衡提升为准。

## 4. 对照组与系统配置

### 4.1 对照组

| 方法 | 定义 | 作用 |
| --- | --- | --- |
| `baseline_rag` | 标准单轮检索 + 直接回答 | anchor baseline |
| `baseline_budget_matched` | 预算匹配的单轮控制基线 | 排除“只是多花预算” |
| `baseline_single_round_strong` | 更强检索与更长回答的单轮基线 | 排除“只是单轮检索更强” |
| `edge_agent` | 任务路由式协议、迭代检索、fact memory、budget guard、early-stop、refine gate | 主方法 |

### 4.2 主方法
本文的主方法不再表述为笼统的“通用 agent”，而统一表述为：`budget-aware task-routed protocol for 4B long-context reasoning`。其关键机制包括：
- 任务感知的协议路由
- 预算约束下的迭代检索
- fact memory
- early-stop
- refine gate
- promotion guard

## 5. 实验流程

### 5.1 正式主流程
正式主流程固定为：

`prepare -> index -> baseline -> compare_controls -> agent -> eval -> ablations -> canonical 3-seed confirm`

### 5.2 轮次策略
Round 0：
- 在 canonical 上执行门槛校准；
- 固定四路对照与当前主 agent；
- 冻结当前 4B 主门槛来源文件。

Round 1 以后：
- 每轮先跑 `dev100 + holdout100 + quickgate30`；
- 只有三者同时满足晋级条件时，才进入 canonical；
- 每轮只允许一个主因子变化；
- 若 canonical 失败，则下一轮只针对当前失败模式做单点修正；
- 若连续两轮 canonical 无显著提升，则停止调参，转为补充实验与写作。

冻结规则：
- canonical 连续两轮通过后，再执行 `3-seed = 42 / 123 / 2026`；
- `3-seed + CI` 通过后冻结主配置；
- 冻结后才启动 student 分支和 `code_qa` 外部效度补充。

### 5.3 Student 分支
- student 不进入主实验通过链路；
- 只有 canonical 主配置冻结后才运行；
- 评测顺序固定为：
  - `holdout100`
  - `canonical`

## 6. 评价指标与门槛

### 6.1 主指标
- overall F1
- `single_doc_qa / multi_doc_qa / code_qa` F1
- `P95 ratio`
- `oom_count`

### 6.2 主门槛

| 指标 | formal gate |
| --- | --- |
| overall F1 | `>= 0.34` |
| single_doc_qa F1 | `>= 0.29` |
| P95 ratio | `<= 1.80` |
| oom_count | `= 0` |

### 6.3 Paper-ready 目标
formal gate 只决定“是否通过”，不直接等同于论文目标。本文的 paper-ready 目标采用两层口径。

#### Canonical 主结论目标
- overall F1：相对 `baseline_rag_4b` 提升 `+0.015` 到 `+0.030`
- `single_doc_qa`：至少非负提升，目标 `+0.010` 以上
- `multi_doc_qa`：目标 `+0.020` 以上
- `code_qa`：目标 `+0.030` 以上
- `P95 ratio <= 1.75`
- `OOM = 0`

#### 亮点任务目标
- 在 `holdout100` 或 `quickgate30` 上，让 `code_qa` 相对 baseline 提升 `+0.20` 以上
- 这条亮点只用于展示高价值任务收益，不替代 canonical 主结论

### 6.4 显著性与稳定性
- canonical 冻结后执行 `3-seed = 42 / 123 / 2026`
- 统一报告 `mean / std`
- 必要时补 `95% CI`

## 9. Student 补充实验
student 章节只回答三件事：
- 与 teacher 相比，质量损失多少；
- 检索次数和时延是否下降；
- 三任务相对排序是否保持一致。

## 10. 实验记录与审计
每轮实验必须输出：
- round snapshot
- 当前 config diff
- 四路对照结果引用
- `dev100 / holdout100 / quickgate30 / canonical` 指标
- failure mode
- next action
- 若已触发，则补 canonical `3-seed confirm`

## 11. 有效性威胁

### 11.1 内部效度
- 小模型对 prompt 与预算更敏感，可能造成轮次间波动；
- 因此本文采用 `last_good_config`、单因子修改与 round snapshot 约束策略漂移。

### 11.2 外部效度
- 本文的正式主结论只针对当前 `Qwen3 4B + local backend + LongBench_3tasks canonical` 条件成立；
- `code_qa` 当前主评测来源偏窄，因此补充 `RepoBench Python valid + RepoBench Java valid` 的固定小样本附录评测；
- 其他模型、后端或数据分布需要重新校准门槛。

### 11.3 统计效度
- 单轮通过不等于稳定通过；
- 论文主结论必须经过 canonical 多 seed 复核。

## 12. 本章结论模板
建议最后结论写法如下：

1. 在 `Qwen3 4B` 条件下，`edge_agent` 在 `LongBench_3tasks canonical` 上相对三类强对照实现了三任务平衡提升。
2. 该收益不能完全由“更高预算”或“更强单轮检索”解释，而更符合任务路由式协议带来的净收益。
3. 质量提升主要来自协议化迭代、fact memory 与 guard / refine 机制，而成本与稳定性的变化可由分组消融解释。
4. `code_qa` 在高价值场景上呈现更大的亮点提升，但本文仍以 canonical 三任务平衡作为唯一主结论。
5. student 路线进一步补充了效率收益，但不替代主实验结论。
