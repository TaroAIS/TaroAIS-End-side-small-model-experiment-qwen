## 5) 运行中暴露的稳定性问题
- HF SSL 抖动会影响 embedding 初始化（日志可见重试/回退），进而影响检索一致性。
- Ollama 在长轮次中出现过一次 `read timeout=120s`；已将 `configs/agent.yaml` 的 `local_backend.request_timeout_s` 调整为 `180`。
- 若 baseline 允许静默回退 lexical，会导致 baseline 过快、ratio 虚高；因此已给 baseline 加 `require_dense_in_formal=true`。

## 6) 当前推荐配置（B2，已回滚到该口径）
- `configs/agent.yaml` 关键值：
  - 全局：`agent.max_steps=3`
  - 检索：`hybrid.enable=true`，`alpha_dense=0.65`，`alpha_lexical=0.35`
  - 预算：`decoding_budget.enable=true`，`short_question_max_new_tokens=176`
  - code_qa：`max_steps=3`，`max_new_tokens=192`
  - multi_doc_qa：`top_k_iter=1`，`max_steps=3`，`max_new_tokens=208`
  - single_doc_qa：`top_k_init=3`，`forced_retrieve.enable=true`，`final_refine_max_new_tokens=128`

## 7) 下一步建议（执行顺序）
1. 固定 embedding 依赖为本地可重复源（避免运行期远程抖动）。
2. 用当前 B2 配置再次做 3-seed（42/123/2026）复核，优先观察 `P95 ratio`。
3. 若 ratio 仍超线，只做一项小改：`single_doc final_refine_max_new_tokens 128 -> 96` 后重测。
4. 若 ratio 达标，再执行“连续两次 3-seed 通过”作为最终停止条件。
